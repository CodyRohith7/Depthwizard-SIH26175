# DepthWizard frontend -- Milestone M1 scaffold

## What this is

A minimal Three.js point-cloud viewer. It loads `public/sample_scene.json`
(generated by `scripts/export_sample_scene.py` from the *real* io -> depth
-> reconstruction chain, in explicit `DEMO_FALLBACK` mode) and displays it
with orbit/pan/zoom via `OrbitControls`. That is the whole M1 scope --
proving the frontend can consume real backend-shaped output. It is
deliberately unstyled.

## Why vanilla Three.js instead of a built React app

The M1 instructions asked for React + Three.js, with an explicit fallback:
*"If the repository architecture makes a simpler vanilla Three.js
implementation more reliable initially, use that."* This development
session has no network access to the npm registry (`npm install three`
was attempted for real and failed with `403 Forbidden`, not a code
problem), so a React/Vite build could not be installed, built, or run
here -- it would be unverified source code with zero evidence it actually
works. The vanilla page above uses an import map to pull Three.js from a
CDN at *view* time instead of *build* time, so:

- No `npm install` is needed to run it at all.
- Its JavaScript syntax has been verified for real with `node --check`
  (Node.js is installed; this only validates syntax, not that the CDN
  imports resolve or that it renders -- see "What is NOT verified" below).
- Once your machine has normal internet access, opening it in a browser
  should just work.

Migrating this to a bundled React + `@react-three/fiber` app later is a
small, well-scoped follow-up (the scene-loading and point-cloud-building
logic in `src/viewer.js` ports over almost directly into a React
component) -- not done now, to avoid maintaining two unverified frontend
stacks in parallel.

## Running it

```
cd frontend
python3 -m http.server 8080   # or: npm run serve
```
then open `http://localhost:8080/`. Opening `index.html` directly via a
`file://` URL will very likely fail: browsers commonly block `fetch()` of
local JSON files from `file://` origins, and this page uses `fetch()` to
load `sample_scene.json`.

Regenerate the sample scene at any time with:
```
PYTHONPATH=src python3 scripts/export_sample_scene.py
```

## What IS verified

- `scripts/export_sample_scene.py` runs for real and produced the checked-in
  `public/sample_scene.json` (12,288 points, ~950 KB) from the real `io` and
  `depth` (DEMO_FALLBACK) modules -- see the top-level README's test log.
- `src/viewer.js`'s syntax is valid ES module JavaScript (`node --check`).

## What is NOT verified

- The page has never been opened in an actual browser in this development
  session (no browser and no network access to the CDN here). Whether
  Three.js loads from the pinned `unpkg.com` URLs, whether `OrbitControls`
  behaves as expected, and whether the point cloud actually renders
  correctly are all unverified. Please run it locally and report back.
